open-source web security scanner

Find the weak spots before attackers do.

ThreatHarbor checks any URL for the web-security mistakes that show up again and again: missing headers, cookies without protection, forms posting over plain HTTP. Run one command, get a color-coded report.

// 01 — checks

What it checks

Five modules, run in order against a single fetch of the page. Each returns findings tagged with a severity.

  1. 01

    Security headers

    Looks for missing response headers (X-Frame-Options, CSP, HSTS, Referrer-Policy, X-Content-Type-Options) and flags servers that leak their software version.

    MediumLowInfo
  2. 02

    Cookie flags

    Inspects every Set-Cookie for the three flags that matter: HttpOnly (hide from JavaScript), Secure (HTTPS only), and SameSite (cross-site defense).

    MediumLow
  3. 03

    Redirects

    Checks whether plain HTTP upgrades to HTTPS, and whether the redirect chain ever jumps to a different host (a possible open redirect).

    MediumLow
  4. 04

    Forms

    Parses every form on the page. Flags forms that submit over HTTP, and POST forms with no field that looks like a CSRF token.

    MediumInfo
  5. 05

    Reflected XSS active

    Submits a probe payload through text inputs and checks whether it comes back unescaped in the HTML. Off by default; only runs with the --unsafe flag.

    High
// 02 — usage

Three commands to your first report

Python 3.10+ and three packages. No accounts, no API keys.

1

Install dependencies

$ pip install -r requirements.txt
2

Scan a URL

$ python main.py --url https://example.com
3

Open the report

$ start report.html

Useful flags

--output
name the report file (default report.html)
--verbose
log findings to the terminal as they run
--timeout
per-request timeout in seconds (default 5, max 10)
--unsafe
enable the active XSS probe (authorized targets only)

// 04 — notes

What this is, and what it isn't

Built as a learning project. Being clear about the limits is part of the point.

Design decisions worth knowing

  • Fetches the target once and shares the response across every check. Fewer round trips, less load on the target.
  • Each check is a plug-in module exposing one run() function. Adding a check is dropping a file in checks/.
  • A failing check is caught and logged as a warning. One broken check never aborts the scan.
  • Severities are deliberately conservative. The weak CSRF heuristic is Info, not a louder level.

Honest limitations

  • Scans one URL. It does not crawl a whole site.
  • No JavaScript rendering. Forms drawn by client-side JS are invisible to it.
  • The XSS check is a basic reflection test, not a full XSS engine.
  • No authentication, no SQL-injection or SSRF testing.

For educational use on systems you own or are explicitly authorized to test. Scanning targets without permission may be illegal.
